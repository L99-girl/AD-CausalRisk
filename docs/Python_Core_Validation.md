# Python四阶段结果一致性

课程SRS将Python职责限定为四阶段工作流及算法HTTP契约。当前固定`deepagent-v1`/`deepagent-causal-warning-v1`除了校验字段和版本，还将质量决定、图、评分和解释绑定到同一份调用请求。此校验适用于原课程合成规则，不能用于验证其他模型的预测。

## 结果校验

`validate_course_result(result, request, CourseContract())`供课程客户端、报告和批处理共用：

- DATA_FUSION按原索引日、最新非空特征、同日重复/冲突及缺失规则核对摘要和全部质量告警；BLOCKED保持null/UNAVAILABLE和实际执行过的单阶段。
- CAUSAL_GRAPH核对节点/边/路径激活、特征来源日及节点证据角色；模型节点不能改称先验，认知/排序节点不能补造采集日。`activePaths`须与图一致。
- WARNING_MODEL核对固定方法标识、原加性规则的逐项数值及最终分数。左右海马均可用时仍优先左侧；左侧0值可用，只有左侧缺失才回退右侧。
- EXPLANATION除总和重构，还逐项核对贡献与方向，`contributionCount`须匹配。两项相反修改抵消、截断后同分、舍入容差内的改写都不能绕过请求绑定。

原分数和贡献仍分别按原规则保留四位小数；方向使用舍入前贡献的±0.002阈值，风险等级使用舍入前总分的0.34/0.65阈值。显示为0.6500的结果可能仍属于MEDIUM，必须保留服务返回的原等级，不能按显示值重新分档。

校验只验证所提供响应是否满足固定演示规则，不调用工作流、评分工具、网络、研究模型或数据库，也不生成新预测。算术复核不能认证响应来源、实际执行或临床效果。原科学限制必须完整且不重复；当前输出审查拒绝额外限制与未知阶段summary元数据，因为这些位置也能夹带未经支持的临床主张。原先允许这些扩展的语义行为已收紧，冻结Schema未修改。新增文案或元数据须先评审规则和调用方。已知质量告警属于当前固定工作流语义，顺序不影响判断，缺失、额外或重复告警均拒绝。

输出审查还核对每个图节点标签、先验边说明/方向、解释标签、message与interpretation。解释文字使用原未舍入贡献的符号；MMSE/MoCA的零项沿用原非负措辞，MMSE_DELTA零项沿用原“暂未上移”措辞，不用显示值或±0.002方向阈值替代。固定词表审查仅适用原课程规则，不是任意医学文本分类器；合格输出仍须人工复核，永远不能因此取得临床使用资格。

接口字段、版本、原评分公式、正常输出和实际阶段耗时未变。Java仍负责AgentClient和业务保存/权限/审计；不能用本模块替代Java端到端验收。失败时客户端不返回伪成功；POST的不可校验响应保持结果未知，恢复工具只GET，批处理停止并且不保存不可信结果/报告。

## 执行与缓存边界

### 可选数值缺失

原AgentRequest允许省略访视的`mmse/moca/cdrSb`及特征的`featureValue`。省略值按缺失参与原融合/警告/阻断：不补0、不从旧访视补齐最新认知；特征较晚缺失仍保留早先非空值，同日缺失与非空值仍冲突，左MRI缺失仍可用右侧。没有任何核心认知时只执行DATA_FUSION并返回BLOCKED/null/UNAVAILABLE。

缺省读取不改写原字典；省略和显式null在原内容/请求身份摘要中仍不同，同runId不能互换。来源路径只引用实际存在且非空的观测；描述矩阵在字段本身不存在的来源位置增加`fieldPresent=false`，显式null和已有完整来源结构保持。缺失敏感性分别统计移除行数和实际非空值数；既有报告显示省略值为缺失，原JSON来源仍不补字段。必填字段、数值范围和严格整数规则不变。

### HTTP正文表示

请求和响应使用唯一的`Content-Type: application/json`，charset可以省略或为单个`UTF-8`，大小写及标准引号不影响判断。重复charset（即使值相同）、扩展charset及其他字符集拒绝；`Content-Encoding`可以省略或为唯一`identity`，重复编码、压缩和编码链均不接受。实际正文必须为UTF-8 JSON，不猜测UTF-16/32；带BOM的JSON也拒绝。原Content-Length、大小、重复JSON键、trace和结果语义检查保持。

请求声明不合规在读取/解析及RunStore之前返回原`415/UNSUPPORTED_MEDIA_TYPE`，实际正文错误仍为原400；拒绝不占用runId或调用评分。客户端用原`RESPONSE_MEDIA_TYPE`、`RESPONSE_ENCODING`或`INVALID_RESPONSE_JSON`拒绝不合规返回。POST发送后的拒绝保留入口绑定与结果未知状态，可按原runId只GET核对；健康响应不合规时不POST、不登记绑定。此处是原UTF-8约定的执行收紧，未增加媒体类型、字段、错误DTO或公共操作。

### 调用端请求绑定

`CourseClient.create`在入口复制并校验请求，随后在任何健康探测、绑定登记或HTTP调用前完成trace与JSON字节预检。发送的字节、本地runId绑定和响应校验使用同一份入口快照。调用者在健康检查或响应等待期间改写原字典，不改变本次授权输入；`result(expected_request=...)`也先复制显式校验基准。局部快照不认证原始来源或实际训练信息。

无效请求、trace、序列化或字节上限在本地拒绝，不发送请求或留下未提交绑定。健康检查失败也不登记绑定。发送已开始后的超时、断线或不可验证响应保留原快照及结果未知标志，供原runId的GET核对；不自动POST、换runId或生成替代结果。已知runId冲突仍沿原HTTP流程处理。

固定结果DTO没有包含每项原始上下文值；当两个请求产生完全相同的可观察结果时，不能仅凭DTO认证原始来源一致。已暴露的来源日期、图证据、贡献和版本仍按原严格校验执行；本轮未添加字段或扩展共同契约。此处修复Python参考客户端，不代表实际Java AgentClient和持久业务已验收。

绑定判断对合法认知/MRI数值使用专用请求身份摘要，将精确等值的整数/浮点整数及带符号零视为同一输入，允许Java把`25`序列化为`25.0`后重放或显式GET核对。原快照及发送内容保持；无容差、无舍入，不合并真实数值、日期、版本、顺序或缺失变化。原`payload_digest`继续用于内容追溯和阶段输入副作用检查，工具把`25`原位改为`25.0`依然属于内容改写并拒绝；此身份规则不认证真实来源或Java业务幂等。

### 服务端执行

工作流和RunStore分别取得请求快照，再执行输入校验、摘要绑定及计算；调用方随后修改原字典不能改变本次runId、版本、输入或缓存摘要。返回对象与缓存、默认限制文本分别复制，修改一次结果不能污染后续运行。

RunStore按runId共享正在执行的计算，计算/校验/等待期间不持全局缓存锁。相同请求共享成功或本次失败，失败等待者不自动再次执行；不同任务和历史查询保持独立。容量包含执行中与完成的唯一runId；执行中GET仍404，不能证明未执行。工作流返回先取副本再校验，将通过校验的同一对象提交为缓存。详见[并发与失败处理](Python_Concurrent_Execution.md)。

评分工具的身份、版本、数据版本和质量标志先核对，再映射四阶段结果；完整结果通过原Schema和上述一致性检查后才能返回或进入易失缓存。工具异常、缺字段、非有限数、错误贡献/分数或错误版本均为安全HTTP500/ASSESSMENT_FAILED，不缓存，也不自动重试。输入已合法时，工具内部抛出的输入型异常同样属于执行失败，不能误报为调用方400。

超出浮点可表示范围的量表/MRI整数和JSON转义中的孤立Unicode代理项属于输入错误，返回HTTP400/VALIDATION_400。合法中文访视编号和demo数据版本仍可用。上述修复没有新增错误DTO、公共操作或模型版本；历史结果仍由Java保存，重启不会从Python恢复。

## 阶段交接与工具副作用

工作流保留独立的原请求快照。融合、图谱和图到评分输入的工具分别获得输入副本，返回值也先取副本；工具如果原位改写收到的输入，返回HTTP500/ASSESSMENT_FAILED。评分工具同样不得改写输入，返回内容先复制再映射解释。工具保留的旧返回引用被后续修改，不会改写已检查的阶段资料。

阶段输出在进入下游前核对：

- DATA_FUSION按同一份原请求重构固定时间选择政策，核对全部选中记录、索引日、原日期/值、质量阻断、缺失和告警代码；错误融合不能调用图或评分。
- CAUSAL_GRAPH核对原固定模板的完整节点、边、路径、版本、来源日和说明；错误图不能调用图门控或评分。候选图仍只用于离线检查。
- 图门控核对原访视序列与每项规范特征的来源、值、日期、单位及顺序。右侧MRI在左侧可用时虽只作上下文，也不能被门控工具静默删改。低于截断、四舍五入同分或未参与最终贡献都不能豁免来源检查。
- WARNING_MODEL检查工具身份、输入未改写及原输出；原最终结果Schema、逐项贡献、质量、图和文案审查仍保留。工具内部抛出的输入型错误也按执行500处理，不回显细节、不缓存、不自动重试。

融合和图验证会用原纯函数重构预期内容，这是确定性政策核对，不是第二次评分、新任务或新工作流阶段。它不构成独立算法验证，也不能认证原始来源、历史可获得日、临床因果或真实训练成员身份。图门控辅助函数保留原有节点/边掩码检查能力，线上工作流仍只使用原固定图。

正常响应字段、顺序、公式、版本与BLOCKED保持；实际阶段耗时包含该阶段的副本和校验开销。内部工具的原位改写及不符合原政策的中间输出不再被接受。Java业务任务、权限、持久化和真正跨语言联调仍分别验收。

## 可复现验证

从仓库根目录运行`python -m unittest discover -s tests -v`。`test_course_result_integrity.py`覆盖独立JSON Schema仍合法的篡改、实际临时HTTP客户端/只读核对/批处理、原100份档案、64种缺失组合，以及方向和等级的舍入边界；`test_course_execution_integrity.py`覆盖工具故障、异常输入、实际400/500、无缓存/无自动重试和对象复制。不需要研究数据或现有8091/8084服务。

`test_course_stage_boundaries.py`覆盖融合/图/门控的下游前拒绝、工具输入改写、同分但来源错误、返回引用隔离、BLOCKED短路及真实临时HTTP500/后续GET404。该验证使用原DEMO结构，不读取研究数据。

`test_course_http_representation.py`覆盖双向charset/内容编码声明、实际UTF-16/32字节、健康预检、发送后未知状态、中文及原缓存重放。异常请求验证零RunStore/零工作流调用，不改变原评分或共同契约。

`test_course_request_identity.py`覆盖精确数值等价的完成/执行中重放、一次成功/失败共享、容量、客户端GET、首个请求/内容摘要保持，以及相邻浮点同分冲突、严格整数和阶段内容改写拒绝。

`test_course_optional_values.py`覆盖冻结Schema允许的64种六信号省略组合、显式null对照、原时间/冲突/回退政策、来源指针、矩阵字段存在性、缺失计划/比较及实际HTTP重放；不改变Schema来排除合法缺失输入。
