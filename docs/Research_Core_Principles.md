# AD-CausalRisk四环节研究主线与推进规范

本规范约束后续研究选题、实现、验收和演示组织。研究目标固定为：

**多源数据融合 → 个体化因果图谱构建 → 因果引导的预警模型建立 → 个体化可解释性分析。**

这条链是研究目标，不是四环节已经完成的声明。研究证据、软件实现、模型交付、业务接通和临床验证分别验收；项目或接口名称中的“causal”不构成因果识别证据。

## 一、任务必须对应主线

每项推进在现有计划内写明以下内容，不另立并行的“最新计划”：

| 项目 | 必须说明 |
| --- | --- |
| 主线归属 | 对应第1/2/3/4环节，可跨环节；工程支撑任务注明服务于哪一环节及其具体依赖 |
| 真实缺口 | 要回答的研究问题或可复现的工程失败，不能只以“增加模型/页面/报告”为目标 |
| 已有基础 | 已关闭任务、可复用代码/模型/输入/结果；为何不能直接复用解决本问题 |
| 执行范围 | 人群、索引时点、输入/来源、划分、对照、数据读取与拟合预算；纯文档/工程任务写适用范围 |
| 完成终点 | 可审查产物、检查、比较判据及停止条件；阴性、不稳定或不可估计也有明确收口方式 |

信息可从现有上下文确定时直接记录并推进，不为填表重复索取已获授权。缺少必要证据时先做不依赖该证据的工作，并保持未知状态。本规范不自动授权新数据扩读、真实拟合、部署或发布，也不撤销既有有效授权。

## 二、四环节的最低验收要求

| 环节 | 必须落实的行为和证据 | 不能用来替代验收的内容 |
| --- | --- | --- |
| 1. 多源数据融合 | 对齐受试者、索引和终点；保留测量日/实际可获得日或代理性质、单位、QC、处理版本、来源和缺失；训练内拟合预处理；明确横断/纵向与回顾性/历史实时边界；交付图和模型实际使用的输入映射 | CSV字段齐全、人口学补齐、表名存在、演示特征矩阵或把未知值填0，均不证明研究输入合格或临床融合完成 |
| 2. 个体化因果图谱构建 | 明确节点及每类边的含义、方向依据、构建方法和证据等级；区分时间顺序、来源依赖、知识先验、统计关系及已识别因果关系；说明哪些结构共享、哪些节点/边/权重因人变化；学习或选择只用相应训练数据，并评价适用的稳定性 | 共享模板填入个人观测、系数乘个人值、来源连线、先验箭头或重采样方向一致，不能直接称为已识别的个人因果结构/效应 |
| 3. 因果引导的预警模型 | 图须通过有定义的机制实际影响预测，如图指定交互、资格掩码、结构约束或图模型；保留图到实际模型输入/运算的映射；对规定的图变动验证作用，并在同信息集/缺失策略/受试者划分下评价图引导相对对照的增量；区分离线风险预测与业务阈值、预警触发/持久化 | 在表格模型前后画图、算法名称、更多拟合或较高AUC，均不能证明图已参与预测或带来稳定增益。GAT可作为候选方法，但采用GAT也不自动识别因果 |
| 4. 个体化可解释性分析 | 解释绑定同一输入快照、实际使用的图、模型版本和输出策略；说明来源/路径、参考基线、缺失、截断或校准；检查解释对模型的忠实性及适用的个人/跨折/跨模型/参照敏感性，区分全局与局部结论 | 只给全局重要性、图上加文字、归因能重构分数、SHAP/LIME或稳定排序，均不能直接称为个人病因、反事实结论或治疗效果 |

共享结构与个体观测相结合可以是个体化表示，但必须如实注明个体化发生在哪一层；不要求为了形式上的“个体化”给每个人强行学习一张不同的图。

图的规则或结构确实参与计算，只能先证明计算依赖；若要宣称因果效应，还须明确效应问题/估计量、时间顺序、混杂与选择结构及适用的识别假设，并提供相应论证和敏感性证据。未成立时统一使用“先验约束预测”“图交互”“来源关系”“预测归因”等与证据相符的表述，保留因果目标为未完成，不将目标悄然降格或宣称完成。

## 三、当前状态与研究优先级

现有多源输入、固定训练/比较、校准和解释诊断有阶段交付，但四环节没有整体完成。第2→3环节的固定图机制、公平预测比较与解释诊断已有阶段交付；图增益未确立、个人因果与独立/临床证据仍未完成，后续选题仍须围绕这些真实缺口。

当前七/十变量LR、RF、XGBoost是已交付的预测基线，不能一概重命名为已经完成的因果引导模型。旧图指定交互确曾参与预测；固定图增益比较未确立增益，结论保留。课程`DATA_FUSION → CAUSAL_GRAPH → WARNING_MODEL → EXPLANATION`的合成软件闭环，也不能代替真实研究的四环节科学验收。

后续新增科研优先针对上述未完成机制提出明确问题，再按已有输入、证据和协议确定方法。GAT、SHAP/LIME、纵向/测量支持、独立/as-of/QC/临床等仍按具体问题推进；不为了凑齐算法名或页面卡片自动启动实验。

当前唯一下一任务及逐项完成状态以[Python需求状态](Python_Requirement_Status.md)为准。源码可移植交付、Java联调、环境与界面整理属于工程支撑，应有有限终点；不得用其工作量替代第2/3环节科研进展。源码交付复用已有实现，不复制第三套训练器，不为整理源码重训真实模型。

## 四、收口、复用与演示约束

1. 开始前核对已有成果；固定输入/图比较、模型交付和已完成校准/解释任务保持关闭。需要旧产物时直接复用，不因结果阴性而重开同一矩阵、换seed或不断换图寻找阳性。
2. 新研究可以继续训练，但必须对应真实未完成问题，明确与已关闭任务的差异和验收终点；阶段预算耗尽、暂缺外部回复或提交代码均不等于整体研究完成。
3. 每轮结束核对产物、相关检查、实际运行（如适用）、研究结论和未成立项，再更新完成/待协作状态及唯一下一主任务；不把新发现无限追加到本轮，也不不断新增包装器和报告代替解决缺口。
4. 工程测试、模型保存/加载误差0、拟合次数、界面截图分别证明其对应范围，不能代替图增益、解释稳定、独立或临床证据。不同队列、索引、信息集和终点不直接横比改善；受条件限制的区间必须保留限制。
5. 演示默认围绕四环节组织，清楚标注当前模型、队列及预测/因果边界。旧六方案、旧真实记录、OASIS浏览、课程验收和开发状态不得与当前研究成果混为同一模型或证据；历史/教学/开发工具放次级入口，开发计划放文档或维护区。此要求是后续界面改动的验收约束，不表示当前页面已完成调整。
6. 界面精简不等于删除研究证据或阴性对照。原始数据、模型、私有折划分、协议、历史绑定和唯一备份保持；物理清理先核对引用、绑定、替代与恢复依据，不按目录名/版本号批量删除。
7. Java负责业务取数、权限、任务与结果持久化；Python负责计算。模型交付、真实输入接入和Java联合验收分开记录，不在Python复制业务层或用本地合成页面冒充接通；共享契约变化按已有协作规则协调。提交/推送/合并/对外发布继续遵守既有授权边界。

详细当前结果和交付边界见[研究交付与接入说明](Research_Progress_and_Integration.md)。本规范作为持续约束维护；结果数字与任务状态不在此重复维护。
