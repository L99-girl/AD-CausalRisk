四阶段执行入口按runId协调并发，慢任务不挡历史GET及其他任务；同请求共享一次成功或失败，等待者不自动重算；执行中冲突409、容量503，容量计入执行中唯一runId。结果先复制再校验，原BLOCKED、分数、版本和同步语义保持，见[并发与失败处理](Python_Concurrent_Execution.md)。执行中GET仍404，不证明未执行；进程重启、业务幂等和权限仍由Java联调另验收。

四阶段交接现保留原请求快照、隔离工具输入/返回引用并拒绝输入原位改写；融合政策、原固定图和门控来源在下游评分前核对。坏融合/图/门控不再先评分再靠终点拒绝，同分也不能代替来源正确；原工具入口、同步阶段、公式、版本和最终输出审查保持。详见[核心结果校验的阶段交接](Python_Core_Validation.md#阶段交接与工具副作用)。该检查仅核对原确定性政策，不认证真实数据来源、临床因果或模型研究验收。

Python参考客户端也在入口固定请求及GET显式校验基准，发送字节、runId绑定与返回校验使用同一快照；无效trace/JSON/大小在健康探测和绑定前拒绝。调用期间改写调用者对象不改变本次输入，发送后的不确定失败仍只按原runId核对、不自动重提。见[调用端请求绑定](Python_Core_Validation.md#调用端请求绑定)。实际Java客户端、业务幂等/权限/持久化仍需联合验收；DTO未包含的原始上下文值不能仅凭返回内容认证。

双向HTTP正文表示也按原UTF-8 JSON约定检查：拒绝重复/非UTF-8 charset、非identity或重复内容编码，响应不自动猜测UTF-16/32。异常请求声明在进入四阶段前用原415拒绝；不可确认的POST响应仍保留原绑定供GET核对。见[HTTP正文表示](Python_Core_Validation.md#http正文表示)。这不代表实际Java调用、来源真实性或临床性能验收。

DATA_FUSION、CSV预检与响应校验现共享同一时间选择实现。FR-06/07的工程子集增加[26列纵向特征矩阵](Python_Feature_Fusion.md)：认知/MRI窗口首末实测值、变化/实际日率/斜率、APOE最近值、公式/单位/来源、覆盖率和分原因缺失矩阵。仅接受原DEMO请求，不自动进入原评分器，不扩展真实输入；研究五来源中的既有认知斜率保持原定义，不能将此新工程矩阵当真实遗传/MRI研究融合已验收。

RunStore和参考客户端的请求身份比较支持合法认知/MRI数值的精确等价表示（如25与25.0），完成/执行中重放共享原计算及耗时。原内容摘要、快照/发送类型、来源引用和阶段副作用检查保持严格；没有容差或舍入，真实数值/日期/缺失/版本变化仍冲突。详见[并发与失败处理](Python_Concurrent_Execution.md)。此处不改变Java业务幂等职责。

原契约允许省略的认知数值/featureValue现贯通融合、请求身份、路径来源与缺失敏感性。省略按缺失处理，保留原警告/阻断、旧非空特征保留及MRI回退；不补零或改写原请求，省略/null仍保留不同摘要。矩阵仅对字段不存在的位置标注fieldPresent=false；既有报告的省略值显示兼容不代表新增报告范围。详见[可选数值缺失](Python_Core_Validation.md#可选数值缺失)。

原Agent错误现按操作及HTTP状态核对：健康失败不能冒充原run缓存缺失；POST错误声明错配时保留未知及原绑定，仅GET核对。原合法错误/真正缓存缺失/成功及BLOCKED保持，详见[只读恢复](Python_Interop_Recovery.md)。Python错误自验仍不代表实际Java业务错误映射、持久化或幂等验收。

## 研究方向目前不能宣布“没有问题”
