## 研究方向目前不能宣布“没有问题”

已有受控研究产物：六种固定输入/图方案、451名受试者/9082个人月、固定规格指标与序列化复现。这六种方案属于同一类月度多项逻辑风险模型；它们不是RF、XGBoost、GAT等六类算法。当前目录5008名、已有可计算投影50名，也不是5008份已完成临床验证的模型输入。

沿用既有绑定聚合结果，未在本次重新拟合或估计：图方案内部/日历/NACC映射AUC约0.807/0.757/0.733；原图增益标准未通过。NACC图减可获得性对照Brier约+0.004124（更高表示误差更高），校准斜率约0.388；映射终点不等价。AUC不能解释为准确率，现有证据不支持精准个人概率或图方案已证实优越。来源见[研究基底与接入验收](Research_Backend_Acceptance.md)。

## 接下来按顺序推进

1. 优先完成Python自己的四阶段/融合与特征工程：已有共享时间选择及[纵向矩阵](Python_Feature_Fusion.md)，下一步按明确的数据/模型定义接入和验收；不把新增列自动塞进现有模型。课程报告和批处理是已有辅助成果，不再作为核心需求进度的默认替代。
2. 已提供跨语言请求/响应核心、失败/超时/重放/重启场景与只读核对材料，见[跨语言故障与恢复验收](Python_Interop_Recovery.md)；下一步用同学实际AgentClient核对调用与失败映射，再按反馈补明确的HTTP边界。
3. 按Java/前端实际接入完成全链路验收；不把Java未实现的持久化、权限或业务API算成Python单方可完成项。
4. 研究任务依据新证据与固定协议分别推进，优先关闭来源/终点及公平比较问题，再讨论新算法；继续保留不支持图增益和临床精度的结果。

当前功能分支按阶段本地提交。每次推送、共同接口变更、扩大真实输入和科研拟合另按明确授权与既有协议处理，不为显示“进度完成”删除未完成要求。
